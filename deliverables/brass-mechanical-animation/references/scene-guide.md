# 场景与时间轴

## 改哪个文件

`config.json` 控制 width/height/fps/duration、x264的crf/preset、previewTimes。默认24秒的外部时间映射到18秒内部动作。改变画幅只改宽高后，还须检查相机构图，不承诺自动适配竖屏。

`scene.js` 按顺序包含：渲染与灯光 → 固定种子的程序材质 → 几何工具 → 木座与三站 → 导轨/丝杠/齿轮/载体 → 夹持、比较表盘、档案抽屉与分支 → 偏心轮压印 → 车削与雕纹 → 事件与相机曲线 → renderAt。

几何入口：`box/cyl/bar/torus/screw`，齿轮 `gear`，车削件 `turned`，管路 `pipe`。材料在 `M` 中：brass/gold/steel/dark/wood/white等，雕纹用Canvas纹理。随机纹理初始化种子19。所有模块与Three.js依赖在本地。

## 叙事与动作地图

| 内部时间（秒） | 默认外部24秒时间 | 机制 |
| --- | --- | --- |
| 0–3 | 0–4 | 左侧近景，夹具合拢、松开 |
| 3–6.35 | 4–8.47 | 同一象牙色工作件沿丝杠从左站到比较站 |
| 6.7–9.6 | 8.93–12.8 | 扫描头横移、下探，表针变化，档案抽屉短暂伸出 |
| 10–12.9 | 13.33–17.2 | 工作件进入压印站，相机随行 |
| 13.15–14.8 | 17.53–19.73 | 偏心轮/随动杆接触，压头下降并复位 |
| 15–17.6 | 20–23.47 | 后方回程滑块运行，相机升高揭示系统 |

`carrierX(t)` 决定主体位移；丝杠与两齿轮由同一travel值驱动。夹爪、抽屉、表针和压头每帧都从绝对时间计算。`poseKeys` 的每项是 `[内部秒数, 相机位置[x,y,z], 注视目标[x,y,z], fov]`，位置与目标分别插值，避免目标被动绑在镜头中央。

压头的位移由偏心圆与随动杆交点解析计算；这只说明该局部运动的几何关系。整个装置没有动力学解算，也不保证齿形、所有传动比和制造配合满足工程要求。

## 换一个主题

先写简短映射，例如「多源收集→夹持进料；证据比较→比较器与表盘；复核→压印前闸门」。如果语义有不确定状态、退回或人工决定，映射中保留它，不能让无条件的机械落印误传成自动批准。

优先保留工作件的颜色、轮廓、装夹与跨站路径，新增机构承担明确功能。大改站点坐标时同步检查共享导轨、支座、管路端点、相机目标与动作时段。不要仅把一堆盒体涂成黄铜，再让相机巡游。

增加时长时让时间轴和声音事件共同扩展。`make-foley.cjs` 的事件和窗口使用同一18秒内部时基，经duration缩放。仅改duration可用于预览节奏，但不能冒充新增完整剧情。

## 确定性接口

渲染器只要求页面设置 `window.ready=true`、暴露 `window.sceneInfo` 和同步的 `window.renderAt(seconds)`。后者渲染当前状态并可返回状态信息。不要依赖requestAnimationFrame推进、真实时钟、累加旋转或调用先后顺序；需要异步资源时全部就绪后再置ready。

内部HTML没有播放循环是有意设计：渲染器按绝对时间调用。双击HTML或浏览器停留在首帧不能代替MP4播放；需要调试时由本地HTTP服务访问，通过浏览器控制台调用renderAt。
